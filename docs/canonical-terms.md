## 1. Product Name

### Personal Consultant

- **Meaning:** приватний персональний бізнес-консультант і коуч для одного власника з повсякденною консультацією в захищеній Element/Matrix-кімнаті та єдиною вузькою веб-поверхнею `Налаштування власника`.
- **Use when:** називаємо продукт, систему або проєкт.
- **Avoid:** `публічний чатбот`, `SaaS`, назви конкретних консалтингових фірм або твердження про реальне працевлаштування в них.
- **Notes:** у коді, назвах файлів і заголовках зберігати написання `Personal Consultant`; у природному українському тексті допустиме пояснення `персональний бізнес-консультант і коуч`. Це не SaaS і не сервіс для третіх осіб.

## 2. User Roles

### Власник

- **Meaning:** єдиний користувач V1, джерело запиту, остаточний носій рішення й дозволу.
- **Use when:** описуємо роль користувача в доступі, сесії, архіві або зовнішній дії.
- **Avoid:** `клієнт`, `адміністратор`, `член команди` як окремі ролі V1.
- **Notes:** у прямому повідомленні до користувача природно використовувати `ви`.

### Головний консультант

- **Meaning:** Codex-агент, який приймає запит, визначає режим, добирає агентів, реєструє підтверджені міжагентні повідомлення, керує дискусією та відповідає за фінальну рекомендацію.
- **Use when:** називаємо єдиного відповідального за процес і синтез.
- **Avoid:** `оркестратор`, `головний агент`, `модератор` або `реєстратор` як окремі користувацькі ролі.
- **Notes:** `реєстратор` — відповідальність головного консультанта під час консиліуму, а не додатковий учасник. Головний консультант працює в окремій реальній Codex-сесії/треді.

### Codex-агент-спеціаліст

- **Meaning:** окремо запущений ШІ-агент, який виконує обмежену предметну частину консиліуму.
- **Use when:** потрібно відрізнити спеціаліста від головного консультанта й критика.
- **Avoid:** загальне `експерт`, `партнер фірми`, `живий консультант` або `субагент`, якщо йдеться про роль, видиму власнику.
- **Notes:** у чаті показувати конкретну предметну роль, наприклад `Фінансовий консультант`, а не технічний ID агента. Кожен спеціаліст має окрему реальну Codex-сесію/тред; усі вони використовують один захищений ChatGPT OAuth-стан власника.

### Claude Code-агент-критик

- **Meaning:** окремий агент, який незалежно перевіряє ключову пропозицію, докази, альтернативні пояснення, ризики й умови провалу.
- **Use when:** називаємо підтверджену роль критика V1.
- **Avoid:** `Claude`, `критик` або `red team` без уточнення ролі в нормативному тексті.
- **Notes:** згода критика або інших агентів не є незалежним доказом без зовнішніх даних чи першоджерел. Для довіреної автоматизації критик автентифікується через subscription OAuth token від `claude setup-token`, а не через Anthropic API key.

### Зовнішній провайдер

- **Meaning:** Google, `matrix.org`, Cloudflare, OpenAI або Anthropic як постачальник ідентифікації, транспорту, синхронізації, розміщення чи агентських можливостей.
- **Use when:** описуємо передачу даних, залежності або межі відповідальності.
- **Avoid:** називати провайдера користувачем продукту.
- **Notes:** конкретні назви провайдерів не замінювати узагальненням, коли вони важливі для згоди на обробку даних.

## 3. Core Domain Objects

### Запит

- **Meaning:** повідомлення або набір матеріалів власника з практичним питанням чи проблемою.
- **Use when:** описуємо вхід до прямої відповіді або консиліуму.
- **Avoid:** `промпт` у користувацькому тексті.
- **Notes:** запит може містити текст, зображення або PDF.

### Сесія

- **Meaning:** один відокремлений цикл роботи над поточним запитом із власним контекстом, повідомленнями, витратами та архівним результатом.
- **Use when:** описуємо активну роботу, команди, завершення, експорт або видалення.
- **Avoid:** `тред`, `ран`, `чат-сесія` без потреби.
- **Notes:** у V1 одночасно існує не більше однієї активної сесії.

### Консиліум

- **Meaning:** режим роботи кількох реально й окремо запущених агентів-спеціалістів, які формують незалежні позиції, обмінюються адресованими повідомленнями та проходять критику перед фінальним синтезом.
- **Use when:** задача перетинає кілька сфер, має високу ціну помилки, потребує незалежної критики або власник прямо просить консиліум.
- **Avoid:** називати консиліумом один монолог, стилізований під кілька ролей.
- **Notes:** типовий склад V1 — головний консультант, 2–5 Codex-агентів-спеціалістів і Claude Code-агент-критик.

### Підтверджена репліка агента

- **Meaning:** фактично надіслане й зареєстроване повідомлення агента з незмінним тілом і визначеним порядком.
- **Use when:** описуємо те, що негайно показується в Element та входить до архіву.
- **Avoid:** `думки агента`, `внутрішні міркування`, `лог інструмента` або синтетична репліка.
- **Notes:** після реєстрації виправлення можливе лише новою реплікою.

### Дослівний консиліум

- **Meaning:** обраний змістовий і UX-напрям Candidate B, у якому всі фактично надіслані агентські доручення, проміжні репліки, критика й виправлення повністю видно наживо без редагування, переказу, приховування або пакетування до фіналу.
- **Use when:** описуємо канонічний досвід складної консультації V1.
- **Avoid:** прирівнювати до нього приховані міркування моделей, системні промпти чи журнали інструментів або імітувати кілька ролей одним монологом.
- **Notes:** усі ролі агентів і час `HH:MM` показуються всередині повідомлень одного Matrix-акаунта бота.

### Фінальна рекомендація

- **Meaning:** один синтезований результат головного консультанта: рішення, до трьох дій, критичні ризики/припущення/умова перегляду і, за потреби, окрема технічна частина.
- **Use when:** називаємо завершальний користувацький результат прямої консультації або консиліуму.
- **Avoid:** `сирий звіт агентів`, `компіляція відповідей`, `final answer`.
- **Notes:** суперечності синтезує головний консультант; користувач не повинен сам узгоджувати монологи.

### Технічна частина

- **Meaning:** окремий самодостатній блок із технічним результатом, який можна цілком перенести в Codex.
- **Use when:** технічне виконання справді є частиною рекомендації.
- **Avoid:** дробити її на фрагменти, які користувач має складати вручну, або додавати без потреби.
- **Notes:** не змішувати з головним висновком і діями.

### Дозволена Matrix-пара

- **Meaning:** точна дозволена комбінація `room_id` приватної E2EE-кімнати й `owner_mxid` єдиного власника, що може запускати робочі запити й отримувати захищені дані V1.
- **Use when:** описуємо контроль доступу.
- **Avoid:** `дозволений номер`, `адмінський акаунт`, `білий список` або перевірку лише одного з двох значень.
- **Notes:** внутрішній технічний термін — `allowlist`; пристрій також має бути перевіреним і не відкликаним.

### Приватна Matrix-кімната

- **Meaning:** єдина кімната V1 лише за запрошенням з обов'язковим E2EE, у якій присутні один Matrix-акаунт власника й один Matrix-акаунт бота.
- **Use when:** називаємо єдину поверхню та канал повсякденної консультації.
- **Avoid:** `публічна кімната`, кілька робочих кімнат або окремий акаунт для кожної агентської ролі.
- **Notes:** технічний ідентифікатор кімнати — `room_id`; користувацький клієнт — Element.

### Перевірений Matrix-пристрій

- **Meaning:** пристрій власника або бота, криптографічно перевірений у Matrix і допущений до E2EE-сесії.
- **Use when:** описуємо доступ, відновлення, точку завершення E2EE або наскрізну перевірку.
- **Avoid:** вважати самого знання `owner_mxid` достатнім для доступу.
- **Notes:** втрачений або скомпрометований пристрій потрібно відкликати; новий пристрій відновлює ключі через recovery key і проходить перевірку.

### Matrix.org public homeserver

- **Meaning:** публічний Matrix homeserver `matrix.org`, обраний для V1 на поточному безкоштовному плані; він забезпечує транспорт і синхронізацію кімнати.
- **Use when:** описуємо платформну залежність, згоду на обробку даних або облік витрат V1.
- **Avoid:** `власний homeserver`, `власний VPS`, платний Matrix-hosting або локальний Mac як production-сервер V1.
- **Notes:** homeserver отримує зашифрований зміст, але бачить службові метадані Matrix. V1 не заявляє server-level контроль federation і не покладається на `m.federate: false`.

### Matrix E2EE

- **Meaning:** наскрізне шифрування змісту Matrix-подій між перевіреними пристроями власника й бота.
- **Use when:** точно описуємо захист транспорту й межу довіри.
- **Avoid:** стверджувати, що E2EE приховує службові метадані від homeserver або поширюється на Cloudflare, OpenAI чи Anthropic після розшифрування ботом.
- **Notes:** E2EE завершується на verified Matrix device бота в Cloudflare runtime; розшифрований зміст існує в пам'яті runtime і передається OpenAI та Anthropic через TLS.

### Згода на обробку даних

- **Meaning:** одноразове підтвердження звичайної обробки бізнес-даних через `matrix.org`, Cloudflare, OpenAI та Anthropic.
- **Use when:** описуємо перший запуск і базову межу передачі даних.
- **Avoid:** вважати її дозволом на особливо чутливий документ або зовнішню дію.
- **Notes:** особливо чутливий документ потребує окремого підтвердження.

### Особливо чутливий документ

- **Meaning:** документ, перед обробкою якого система має отримати окреме підтвердження власника.
- **Use when:** спрацьовує підтверджена високоризикова межа даних.
- **Avoid:** мовчки обробляти його на підставі лише одноразової загальної згоди.
- **Notes:** точна класифікація чутливості належить подальшому уточненню політик, але вимога окремого підтвердження вже є канонічною.

### Секрет

- **Meaning:** пароль, API-ключ, OAuth token або refresh state, Codex `auth.json`, `CLAUDE_CODE_OAUTH_TOKEN`, recovery key, повні карткові чи банківські реквізити, державний ідентифікатор, медичні дані або інші дані, які за продуктовою політикою не можна приймати чи журналювати.
- **Use when:** описуємо дані, які потрібно зупинити до передачі агентам і реєстрації.
- **Avoid:** включати секрет до Matrix-повідомлення, агентського промпту, технічного журналу, архіву, експорту або клієнтського коду.
- **Notes:** термін описує заборонену категорію даних, а не окрему функцію V1.

### Архів сесій

- **Meaning:** зашифроване безстрокове сховище завершених сесій із незмінним змістом і порядком підтверджених повідомлень.
- **Use when:** описуємо подальший доступ, експорт, незмінність або видалення цілої сесії.
- **Avoid:** `історія чату`, якщо важливі гарантії шифрування й незмінності; `резервна копія`, якщо йдеться про канонічний архів.
- **Notes:** окремі репліки завершеної сесії не редагуються й не видаляються.

### Облік витрат

- **Meaning:** налаштовані щомісячні платежі за ChatGPT/Codex і Claude, фактичні інфраструктурні витрати та доступний provider usage/limit/reset status.
- **Use when:** описуємо результат команди `Витрати`.
- **Avoid:** `вартість токенів сесії`, `фактична AI-вартість сесії` або `бюджетний ліміт`, якщо провайдер не нарахував і не надав відповідну суму.
- **Notes:** AI-usage у межах підписки позначається як `входить у підписку` разом зі статусом квоти; невідома сума лишається невідомою. V1 не переходить на PAYG після вичерпання квоти.

### Налаштування власника

- **Meaning:** єдина вузька адаптивна веб-поверхня V1 для параметрів майбутніх консультацій.
- **Use when:** Власник переглядає або змінює `Моделі`, `Глибину міркування` чи `Швидкість` на desktop або mobile.
- **Avoid:** `settings dashboard`, `чат`, `архів`, `admin console`, `панель керування`, `клієнтський кабінет` або назва повсякденного консультаційного UX.
- **Notes:** повсякденна консультація лишається в Element/Matrix; ця поверхня не показує чат, live execution status або архів.

### Google-вхід

- **Meaning:** окрема перевірка особи Власника для доступу до `Налаштувань власника` через Google-акаунт із точною дозволеною email-адресою.
- **Use when:** описуємо доступ до веб-поверхні Settings і fail-closed відмову для іншої email-адреси або невалідного Access JWT.
- **Avoid:** називати входом до Codex, Claude Code, ChatGPT чи AI-підписок; `пароль`, `OTP`, `magic link`, інший IdP або публічна реєстрація не є його варіантами.
- **Notes:** Google-вхід відокремлений від `Subscription OAuth` і не відкриває його секрети.

### Моделі

- **Meaning:** група `Налаштувань власника` з двома окремими виборами: дозволена модель для Codex-агентів і дозволена модель для Claude Code-агента-критика.
- **Use when:** Власник обирає модель із типізованого списку дозволених значень.
- **Avoid:** довільний model slug, free-text input, одна спільна модель для обох провайдерів або неперевірена назва.
- **Notes:** конкретні allowlists і стан доступності визначає перевірювана capability map; невідоме значення fail closed блокує нову сесію.

### Глибина міркування

- **Meaning:** група `Налаштувань власника` зі спільною семантикою `low / medium / high / xhigh` для Codex і Claude Code runtimes.
- **Use when:** Власник задає бажану глибину, а система перевіряє підтримку обома обраними моделями та застосовує валідне provider-specific відображення.
- **Avoid:** мовчазний downgrade, неперевірене provider-specific значення або різні користувацькі шкали для двох провайдерів.
- **Notes:** непідтримуване або невідоме поєднання fail closed блокує нову сесію.

### Швидкість

- **Meaning:** група `Налаштувань власника`, що визначає оркестраційний темп майбутньої консультації.
- **Use when:** називаємо всю групу, в якій Власник обирає один `Пресет швидкості`.
- **Avoid:** `Claude Fast Mode`, платний speed mode, API/PAYG fallback або придбання usage credits.
- **Notes:** група змінює лише дозволену оркестраційну поведінку й не послаблює обов'язкові перевірки.

### Пресет швидкості

- **Meaning:** одне з трьох значень `швидко / збалансовано / ретельно`, яке керує складом і паралельністю консиліуму, глибиною перевірок та очікуваним темпом.
- **Use when:** називаємо конкретно вибране значення групи `Швидкість`.
- **Avoid:** `Fast Mode`, `reasoning effort`, платний режим провайдера або гарантія скороченого часу за рахунок critic/A2A/E2EE/verbatim/safety/privacy.
- **Notes:** жодний пресет не вмикає Claude Fast Mode, API/PAYG або usage credits.

### Фактичні налаштування сесії

- **Meaning:** незмінний snapshot валідних значень `Моделі`, `Глибина міркування` і `Швидкість`, зафіксований для конкретної сесії до першого залежного модельного виклику.
- **Use when:** пояснюємо, з якими параметрами реально працює активна або завершена сесія.
- **Avoid:** `поточні defaults`, `останній saved set` або припущення, що save/reset посеред активної сесії змінює її роботу.
- **Notes:** нове збереження застосовується лише до наступної сесії; несумісний набір не створює snapshot і блокує старт.

## 4. User Actions

### Надіслати запит

- **Meaning:** надіслати текст, зображення або PDF у дозволену приватну E2EE Matrix-кімнату через Element.
- **Use when:** описуємо початок прямої відповіді або консиліуму.
- **Avoid:** `створити тікет`, `запустити промпт`.
- **Notes:** непідтримуваний тип вкладення має отримати зрозуміле повідомлення без запуску аналізу.

### Уточнити задачу

- **Meaning:** надіслати нове звичайне повідомлення під час активної сесії; воно додається до поточного контексту.
- **Use when:** власник коригує або доповнює активний запит.
- **Avoid:** створювати паралельну сесію без команди `Нова задача`.
- **Notes:** слово `задача` зберігається в назві команди та природному описі роботи; об'єкт вхідного повідомлення канонічно називається `запит`.

### `Стоп`

- **Meaning:** команда негайно припинити активну роботу поточної сесії.
- **Use when:** власник хоче зупинити аналіз і подальші витрати.
- **Avoid:** продовжувати нові модельні виклики або публікувати пізні відповіді як продовження зупиненої роботи.
- **Notes:** написання команди зберігати точно як `Стоп`.

### `Нова задача`

- **Meaning:** команда закрити поточну сесію та створити нову без змішування контекстів.
- **Use when:** власник переходить до іншої проблеми.
- **Avoid:** переносити робочий контекст попередньої задачі як активний контекст нової.
- **Notes:** написання команди зберігати точно як `Нова задача`.

### `Витрати`

- **Meaning:** команда показати налаштовані місячні платежі за AI-підписки, фактичні інфраструктурні витрати й доступний статус використання, ліміту або часу відновлення квоти.
- **Use when:** власник перевіряє витрати.
- **Avoid:** подавати token estimate як фактичну суму, приписувати subscription usage ціну за сесію або називати команду механізмом жорсткого ліміту.
- **Notes:** написання команди зберігати точно як `Витрати`; якщо провайдер не надає потрібний показник, відповідь каже `невідомо`.

### Підтвердити окремий дозвіл

- **Meaning:** явно погодити обробку особливо чутливого документа, продовження понад 10 хвилин, зовнішню дію або іншу високоризикову межу.
- **Use when:** система назвала конкретну дію, причину та межу дозволу.
- **Avoid:** виводити такий дозвіл із мовчання, загальної згоди на дані або попереднього дозволу на іншу дію.
- **Notes:** дозвіл має бути окремим і явним.

### Експортувати сесію

- **Meaning:** отримати повний запис однієї сесії зі збереженням змісту й порядку.
- **Use when:** власник хоче перенести або зберегти сесію поза архівом.
- **Avoid:** експортувати лише переказ замість повної сесії.
- **Notes:** експорт не змінює архівний запис.

### Видалити сесію

- **Meaning:** остаточно видалити всю сесію після явного підтвердження.
- **Use when:** власник контролює зберігання своїх даних.
- **Avoid:** `видалити репліку`, `відредагувати архів` або видалення без підтвердження.
- **Notes:** окремі повідомлення завершеної сесії не видаляються.

## 5. Product States

### Пряма відповідь

- **Meaning:** робочий режим для короткого фактичного або очевидно простого запиту без зайвого консиліуму.
- **Use when:** кілька фахових позицій чи незалежна критика не потрібні.
- **Avoid:** запускати агентів лише для демонстрації процесу.
- **Notes:** це режим роботи, а не тип користувача.

### Консиліум

- **Meaning:** робочий режим для складної, багатосферної, високоризикової або прямо позначеної користувачем задачі.
- **Use when:** виконано хоча б одну підтверджену умову скликання.
- **Avoid:** використовувати для простого фактичного питання або невеликої безпечної дії.
- **Notes:** див. також об'єкт `Консиліум` у розділі 3.

### Активна сесія

- **Meaning:** поточна сесія, яка приймає уточнення й у межах якої триває робота.
- **Use when:** описуємо єдиний активний контекст V1.
- **Avoid:** кілька паралельних активних сесій.
- **Notes:** нове звичайне повідомлення додається саме до неї.

### Очікування дозволу

- **Meaning:** сесія призупинила відповідну дію до окремого явного рішення власника.
- **Use when:** потрібне продовження понад 10 хвилин, обробка особливо чутливого документа, зовнішня дія або інша підтверджена високоризикова межа.
- **Avoid:** називати станом помилки або мовчки продовжувати роботу.
- **Notes:** причина й запит дозволу мають бути видимими.

### Зупинена сесія

- **Meaning:** сесія, роботу якої власник припинив командою `Стоп`.
- **Use when:** потрібно пояснити, чому нові виклики й пізні агентські повідомлення не продовжують цю роботу.
- **Avoid:** `завершена успішно`.
- **Notes:** точний спільний lifecycle для сесій, закритих через `Нова задача`, залишається відкритим словниковим питанням.

### Завершена сесія

- **Meaning:** сесія, у якій роботу завершено й канонічний запис переведено до зашифрованого незмінного архіву.
- **Use when:** описуємо нормальне завершення, подальший експорт або видалення.
- **Avoid:** називати завершеною сесію з прихованим збоєм, неповним результатом або непідтвердженим архівом.
- **Notes:** завершення не означає права редагувати окремі репліки.

### Збій або неповний результат

- **Meaning:** видимий стан, коли агент, провайдер або частина роботи недоступні чи доказів недостатньо.
- **Use when:** фактичний результат не відповідає повному успішному сценарію.
- **Avoid:** маскувати його статусом успіху або вигаданою реплікою.
- **Notes:** система має назвати наслідок і наступну можливу дію.

## 8. Internal Terms

### Subscription OAuth

- **Meaning:** автентифікація Codex або Claude Code через платну підписку єдиного власника без API-key/PAYG-білінгу.
- **Use when:** описуємо єдиний дозволений AI auth mode V1.
- **Avoid:** називати API key еквівалентом Subscription OAuth, припускати платний fallback або змішувати його з `Google-входом` до `Налаштувань власника`.
- **Notes:** Google-вхід не авторизує Codex або Claude Code. Якщо Subscription OAuth або квота недоступні, залежна робота зупиняється; повторна авторизація відбувається лише через захищений позачатовий канал.

### Codex OAuth-стан

- **Meaning:** один авторитетний захищений ChatGPT OAuth credential state, яким Codex керує та який штатно оновлює для всіх реальних агентських сесій/тредів власника.
- **Use when:** описуємо Codex auth, managed refresh або захищене зберігання file-backed `auth.json`.
- **Avoid:** копіювати `auth.json` між незалежними runtime, вкладати його в образ, репозиторій, Matrix, промпти, логи чи архів.
- **Notes:** один auth state не означає один агент: головний консультант і спеціалісти працюють у різних реальних Codex-сесіях/тредах.

### Claude Code OAuth token

- **Meaning:** `CLAUDE_CODE_OAUTH_TOKEN`, створений командою `claude setup-token` для довіреної автоматизації в межах підписки власника.
- **Use when:** описуємо автентифікацію Claude Code-агента-критика.
- **Avoid:** `ANTHROPIC_API_KEY`, API Console PAYG або передавання token через Matrix.
- **Notes:** це секрет; його зберігання, відкликання й повторна авторизація відбуваються поза користувацьким чатом.

### Реальна Codex-сесія/тред

- **Meaning:** окремо запущений контекст виконання одного Codex-агента з власною роллю, завданням і адресованими A2A-повідомленнями.
- **Use when:** доводимо, що головний консультант і кожен спеціаліст є окремими агентами, а не ролями одного монологу.
- **Avoid:** `Matrix-тред`, `Сесія` користувацької задачі або окремий OAuth-акаунт для кожного агента.
- **Notes:** усі такі сесії/треди використовують один Codex OAuth-стан власника, але мають незалежні робочі контексти.

### Fail-closed auth/quota

- **Meaning:** правило, за яким runtime не запускає або зупиняє залежного агента, якщо subscription OAuth mode не підтверджено, refresh не вдався чи квоту вичерпано.
- **Use when:** описуємо реакцію на auth/quota failure.
- **Avoid:** непомітний fallback на `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, PAYG або usage credits.
- **Notes:** видиме повідомлення має назвати причину, доступний reset time і безпечний наступний крок, якщо ці дані відомі.

### A2A

- **Meaning:** підтверджений протокол адресованої міжагентної комунікації.
- **Use when:** описуємо внутрішню взаємодію агентів або подальші технічні рішення.
- **Avoid:** використовувати абревіатуру без пояснення в першому користувацькому згадуванні.
- **Notes:** точна версія та реалізація ще не визначені.

### Реєстратор

- **Meaning:** функція головного консультанта, який підтверджує, упорядковує й реєструє міжагентні повідомлення.
- **Use when:** описуємо внутрішню відповідальність за повноту й порядок.
- **Avoid:** створювати окрему роль `агент-реєстратор` без нового продуктового рішення.
- **Notes:** міжагентні повідомлення в обхід головного консультанта-реєстратора заборонені.

### Канонічний порядок

- **Meaning:** порядок підтвердженої реєстрації агентських повідомлень.
- **Use when:** зіставляємо Element-відображення, архів та експорт.
- **Avoid:** покладатися на час доставки клієнтом як єдине джерело порядку.
- **Notes:** конкретний механізм реалізації належить архітектурі.

### Незмінний журнал сесії

- **Meaning:** внутрішній канонічний запис повного тіла й порядку підтверджених реплік, який після завершення не редагується.
- **Use when:** описуємо цілісність, аудит або формування архіву.
- **Avoid:** `чат` як достатнє пояснення гарантії незмінності.
- **Notes:** точний формат і сховище ще не визначені; старий локальний `CHAT.md` є evidence, а не автоматичною вимогою до формату Matrix V1.

### Allowlist

- **Meaning:** внутрішній технічний механізм перевірки точної пари `room_id` і `owner_mxid` разом зі станом Matrix-пристрою.
- **Use when:** у коді або інтеграційній документації доречний англійський термін.
- **Avoid:** у звичайному користувацькому тексті.
- **Notes:** користувацький термін — `Дозволена Matrix-пара`; неперевірений або відкликаний пристрій не допускається.

### Нативне форматування Element/Matrix

- **Meaning:** читабельне відображення заголовків, абзаців, списків, таблиць, посилань і коду засобами, сумісними з Element/Matrix, без сирого Markdown як коду чату.
- **Use when:** описуємо формат видимої репліки.
- **Avoid:** обіцяти конкретний рендер без перевірки клієнта.
- **Notes:** точні правила перетворення належать downstream-реалізації.

### `room_id`

- **Meaning:** стабільний технічний ідентифікатор єдиної дозволеної Matrix-кімнати.
- **Use when:** описуємо allowlist або перевірку вхідної Matrix-події.
- **Avoid:** показувати як службове поле у звичайній видимій репліці.
- **Notes:** доступ визначає лише точна пара з `owner_mxid`, а не `room_id` окремо.

### `owner_mxid`

- **Meaning:** повний Matrix user ID єдиного власника в allowlist.
- **Use when:** описуємо технічну перевірку відправника.
- **Avoid:** називати номером телефону або вважати достатнім без `room_id` і перевіреного пристрою.
- **Notes:** у звичайному користувацькому тексті використовувати роль `Власник`.

### Recovery key

- **Meaning:** Matrix-механізм відновлення доступу до зашифрованих даних на новому пристрої.
- **Use when:** описуємо контрольоване відновлення після заміни або втрати пристрою.
- **Avoid:** публікувати, журналювати чи передавати recovery key агентам або AI-провайдерам.
- **Notes:** після відновлення новий Matrix-пристрій має пройти перевірку; втрачений або скомпрометований пристрій відкликається.

| `історія чату`, `лог`, `транскрипт` | `Архів сесій` або `незмінний журнал сесії` | Обрати користувацький або внутрішній термін за контекстом. |
| `видалити чат` | `Видалити сесію` | Видаляється ціла сесія після підтвердження. |
| `browser-preview`, `праве прев'ю`, `live-preview` | `локальний evidence-інструмент` | Не називати користувацькою поверхнею V1. |
| `вартість токенів сесії`, `AI-вартість сесії` | `Облік витрат` | Для subscription usage не вигадувати per-session charge; показувати місячні платежі, фактичну інфраструктуру й quota/status. |
| `ChatGPT login`, `Codex credentials`, `auth.json` як auth-модель | `Codex OAuth-стан` | `auth.json` є можливим file-backed секретним носієм, а не користувацькою функцією чи окремим агентом. |
| `Claude token`, `setup token` | `Claude Code OAuth token` | У нормативному тексті вказувати subscription OAuth і секретний характер token. |
| `agent run`, `Codex thread` | `Реальна Codex-сесія/тред` | Не змішувати з користувацькою `Сесією` або Matrix thread. |
| `settings`, `налаштування`, `settings page` | `Налаштування власника` | Це єдина вузька веб-поверхня, не чат, дашборд, архів або admin console. |
| `Google login`, `Google auth`, `settings auth` | `Google-вхід` | Використовувати лише для доступу до `Налаштувань власника`; не називати ним auth Codex/Claude. |
| `AI OAuth`, `provider OAuth`, `вхід до Codex/Claude` | `Subscription OAuth` | Не змішувати з Google-входом; це окрема секретна auth-межа платних AI-підписок. |
| `model`, `model selector`, `model slug` | `Моделі` | Вибір лише з окремих typed allowlists; довільний slug не є дозволеним значенням. |
| `reasoning effort`, `reasoning depth` | `Глибина міркування` | Користувацька шкала завжди `low / medium / high / xhigh` із capability validation. |
| `speed`, `mode`, `швидкісний режим` | `Швидкість` | Назва групи; конкретне значення називати `Пресет швидкості`. |
| `fast`, `balanced`, `careful`, `режим швидко` | `Пресет швидкості` | Канонічні значення: `швидко / збалансовано / ретельно`; це не Claude Fast Mode. |

## 10. Terms to Avoid

- `воронка продажів`.
- `Публічний чатбот`, `SaaS`, `командний акаунт`, `клієнтський кабінет` — цих ролей і поверхонь немає у V1.
- `Живі партнери`, `реальні консультанти фірми` або твердження, що система працює у конкретній консалтинговій компанії.
- `Консиліум`, якщо фактично працював один агент або окремих агентів неможливо було запустити.
- `Незалежний доказ` для самої лише згоди кількох ШІ-агентів.
- `Думки агента`, `ланцюжок міркувань` або `прихований аналіз` як назва видимих реплік; користувач бачить лише фактично надіслані повідомлення.
- `Успішно завершено`, якщо є прихований збій, неповний результат, брак доказів або неперевірений архів.
- `Автоматично виконаємо` для повідомлень третім особам, публікацій, покупок, подання документів, кадрових рішень чи змін зовнішніх систем без окремого дозволу.
- `Browser chat`, `live-preview`, `settings dashboard`, `admin console`, `панель керування` або `архів` як назва `Налаштувань власника` чи повсякденної поверхні V1.
- `Google-вхід` як назва входу до Codex, Claude Code, ChatGPT або AI-підписок; для них канонічний термін — `Subscription OAuth`.
- `Subscription OAuth` як назва доступу до `Налаштувань власника`; для нього канонічний термін — `Google-вхід`.
- `Claude Fast Mode`, `Fast Mode`, `extra usage` або платний provider speed як синонім `Швидкості` чи `Пресету швидкості`.
- Довільний `model slug`, free-text model input або неперевірена назва моделі як доступний вибір V1.
- `Сім груп налаштувань`, `sound/motion settings`, `per-agent override` або `per-unit override` як функції `Налаштувань власника`.
- `WhatsApp` або `Meta WhatsApp Cloud API` як поточний канал V1; ці назви допустимі лише для історичного, superseded або out-of-scope контексту.
- `Власний VPS`, `власний Matrix homeserver` або `локальний Mac` як production-сервер V1.
- `Окремий Matrix-акаунт агента` для кожної видимої ролі; V1 використовує один Matrix-акаунт бота.
- `Власний звук`, `вшшшшух` або інший продуктовий звук; V1 покладається лише на нативні сповіщення Element та операційної системи.
- Твердження, що Matrix E2EE поширюється на Cloudflare, OpenAI чи Anthropic після розшифрування повідомлення verified Matrix device бота.
- Сирі технічні ID, номери повідомлень, секунди, системні інструкції, журнали інструментів і Markdown-маркери в користувацькому чаті.
- `Видалити окрему репліку` або `відредагувати завершену сесію` як доступні дії.
- `Бюджетний ліміт` як функція V1 до окремого підтвердженого рішення після збору фактичних витрат.
- `Фактична вартість модельних викликів сесії`, `token cost сесії` або інша сума, якої провайдер не нарахував і не надав.
- `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `API PAYG`, `автоматичні usage credits` або `fallback на API` як дозволений шлях продовження V1.
- Надсилання `auth.json`, OAuth token, refresh state або reauth URL/code через Matrix, агентський промпт, журнал чи архів.
- `Спільна підписка`, `доступ для клієнтів`, `доступ для команди`, `перепродаж агентів` або SaaS на OAuth-підписках власника.
