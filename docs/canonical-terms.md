## PI-MATRIX-MYSQL-20260908 — Continuity correction terms

Source: current product idea and PRD sections `PI-MATRIX-MYSQL-20260908`; paired with the context correction. `Durable Matrix state` means identity, encryption state and accepted-work recovery data surviving application-file loss (стійкий стан Matrix), not a folder existence check. `Migration` transfers a valid matching store without resetting identity (перенесення стану); `recovery blocked` names unavailable keys or invalid state (відновлення заблоковано), not permission to create a new device. `Fencing` rejects an obsolete writer after ownership changes (відсікання застарілого записувача). `Stateless Preview` remains unable to access Published state; simplifying setup does not waive this boundary.

## 1. Назва продукту

### Personal Consultant

- **Значення:** приватний персональний бізнес-консультант і коуч для одного власника з повсякденною консультацією в захищеній Element/Matrix-кімнаті та єдиною вузькою веб-поверхнею `Налаштування власника`.
- **Вживання:** називаємо продукт, систему або проєкт.
- **Уникати:** `публічний чатбот`, `SaaS`, назви конкретних консалтингових фірм або твердження про реальне працевлаштування в них.
- **Примітка:** у коді, назвах файлів і заголовках зберігати написання `Personal Consultant`; у природному українському тексті допустиме пояснення `персональний бізнес-консультант і коуч`. Це не SaaS і не сервіс для третіх осіб.

## 2. Ролі

### Власник

- **Значення:** єдиний користувач V1, джерело запиту, остаточний носій рішення й дозволу.
- **Вживання:** описуємо роль користувача в доступі, сесії, архіві або зовнішній дії.
- **Уникати:** `клієнт`, `адміністратор`, `член команди` як окремі ролі V1.
- **Примітка:** у прямому повідомленні до користувача природно використовувати `ви`.

### Головний консультант

- **Значення:** Codex-агент, який приймає запит, визначає режим, добирає агентів, реєструє підтверджені міжагентні повідомлення, керує дискусією та відповідає за фінальну рекомендацію.
- **Вживання:** називаємо єдиного відповідального за процес і синтез.
- **Уникати:** `оркестратор`, `головний агент`, `модератор` або `реєстратор` як окремі користувацькі ролі.
- **Примітка:** `реєстратор` — відповідальність головного консультанта під час консиліуму, а не додатковий учасник. Головний консультант працює в окремій реальній Codex-сесії/треді.

### Codex-агент-спеціаліст

- **Значення:** окремо запущений ШІ-агент, який виконує обмежену предметну частину консиліуму.
- **Вживання:** потрібно відрізнити спеціаліста від головного консультанта й критика.
- **Уникати:** загальне `експерт`, `партнер фірми`, `живий консультант` або `субагент`, якщо йдеться про роль, видиму власнику.
- **Примітка:** у чаті показувати конкретну предметну роль, наприклад `Фінансовий консультант`, а не технічний ID агента. Кожен спеціаліст має окрему реальну Codex-сесію/тред; усі вони використовують один захищений ChatGPT OAuth-стан власника.

### Критик

- **Значення:** окремий агент, який незалежно перевіряє ключову пропозицію, докази, альтернативні пояснення, ризики й умови провалу.
- **Вживання:** називаємо підтверджену роль критика V1.
- **Уникати:** називати будь-якого Codex-агента Критиком без окремого призначення цієї ролі.
- **Примітка:** згода критика або інших агентів не є незалежним доказом без зовнішніх даних чи першоджерел. Провайдер Критика — Claude Code або Codex за явним вибором. Для Claude використовується setup-token; для Codex — окремий thread з єдиним керованим OAuth-станом, без копій облікових даних.

### Зовнішній провайдер

- **Значення:** `matrix.org`, GoDaddy, MySQL, OpenAI або Anthropic як постачальник транспорту, синхронізації, розміщення, зберігання чи агентських можливостей; Google — провайдер підтвердження особи для входу Власника (`FR-038`).
- **Вживання:** описуємо передачу даних, залежності або межі відповідальності.
- **Уникати:** називати провайдера користувачем продукту.
- **Примітка:** конкретні назви провайдерів не замінювати узагальненням, коли вони важливі для згоди на обробку даних.

## 3. Основні доменні об'єкти

### Запит

- **Значення:** повідомлення або набір матеріалів власника з практичним питанням чи проблемою.
- **Вживання:** описуємо вхід до прямої відповіді або консиліуму.
- **Уникати:** `промпт` у користувацькому тексті.
- **Примітка:** запит може містити текст, зображення або PDF.

### Сесія

- **Значення:** один відокремлений цикл роботи над поточним запитом із власним контекстом, повідомленнями, витратами та архівним результатом.
- **Вживання:** описуємо активну роботу, команди, завершення, експорт або видалення.
- **Уникати:** `тред`, `ран`, `чат-сесія` без потреби.
- **Примітка:** у V1 одночасно існує не більше однієї активної сесії.

### Консиліум

- **Значення:** режим роботи кількох реально й окремо запущених агентів-спеціалістів, які формують незалежні позиції, обмінюються адресованими повідомленнями та проходять критику перед фінальним синтезом.
- **Вживання:** задача перетинає кілька сфер, має високу ціну помилки, потребує незалежної критики або власник прямо просить консиліум.
- **Уникати:** називати консиліумом один монолог, стилізований під кілька ролей.
- **Примітка:** типовий склад V1 — головний консультант, 2–5 Codex-агентів-спеціалістів і Критик.

### Підтверджена репліка агента

- **Значення:** фактично надіслане й зареєстроване повідомлення агента з незмінним тілом і визначеним порядком.
- **Вживання:** описуємо те, що негайно показується в Element та входить до архіву.
- **Уникати:** `думки агента`, `внутрішні міркування`, `лог інструмента` або синтетична репліка.
- **Примітка:** після реєстрації виправлення можливе лише новою реплікою.

### Дослівний консиліум

- **Значення:** обраний змістовий і UX-напрям Candidate B, у якому всі фактично надіслані агентські доручення, проміжні репліки, критика й виправлення повністю видно наживо без редагування, переказу, приховування або пакетування до фіналу.
- **Вживання:** описуємо канонічний досвід складної консультації V1.
- **Уникати:** прирівнювати до нього приховані міркування моделей, системні промпти чи журнали інструментів або імітувати кілька ролей одним монологом.
- **Примітка:** усі ролі агентів і час `HH:MM` показуються всередині повідомлень одного Matrix-акаунта бота.

### Фінальна рекомендація

- **Значення:** один синтезований результат головного консультанта: рішення, до трьох дій, критичні ризики/припущення/умова перегляду і, за потреби, окрема технічна частина.
- **Вживання:** називаємо завершальний користувацький результат прямої консультації або консиліуму.
- **Уникати:** `сирий звіт агентів`, `компіляція відповідей`, `final answer`.
- **Примітка:** суперечності синтезує головний консультант; користувач не повинен сам узгоджувати монологи.

### Технічна частина

- **Значення:** окремий самодостатній блок із технічним результатом, який можна цілком перенести в Codex.
- **Вживання:** технічне виконання справді є частиною рекомендації.
- **Уникати:** дробити її на фрагменти, які користувач має складати вручну, або додавати без потреби.
- **Примітка:** не змішувати з головним висновком і діями.

### Дозволена Matrix-пара

- **Значення:** точна дозволена комбінація `room_id` приватної E2EE-кімнати й `owner_mxid` єдиного власника, що може запускати робочі запити й отримувати захищені дані V1.
- **Вживання:** описуємо контроль доступу.
- **Уникати:** `дозволений номер`, `адмінський акаунт`, `білий список` або перевірку лише одного з двох значень.
- **Примітка:** внутрішній технічний термін — `allowlist`; пристрій також має бути перевіреним і не відкликаним.

### Приватна Matrix-кімната

- **Значення:** єдина кімната V1 лише за запрошенням з обов'язковим E2EE, у якій присутні один Matrix-акаунт власника й один Matrix-акаунт бота.
- **Вживання:** називаємо єдину поверхню та канал повсякденної консультації.
- **Уникати:** `публічна кімната`, кілька робочих кімнат або окремий акаунт для кожної агентської ролі.
- **Примітка:** технічний ідентифікатор кімнати — `room_id`; користувацький клієнт — Element.

### Перевірений Matrix-пристрій

- **Значення:** пристрій власника або бота, криптографічно перевірений у Matrix і допущений до E2EE-сесії.
- **Вживання:** описуємо доступ, відновлення, точку завершення E2EE або наскрізну перевірку.
- **Уникати:** вважати самого знання `owner_mxid` достатнім для доступу.
- **Примітка:** втрачений або скомпрометований пристрій потрібно відкликати; новий пристрій відновлює ключі через recovery key і проходить перевірку.

### Matrix.org public homeserver

- **Значення:** публічний Matrix homeserver `matrix.org`, обраний для V1 на поточному безкоштовному плані; він забезпечує транспорт і синхронізацію кімнати.
- **Вживання:** описуємо платформну залежність, згоду на обробку даних або облік витрат V1.
- **Уникати:** `власний homeserver`, `власний VPS`, платний Matrix-hosting або локальний Mac як production-сервер V1.
- **Примітка:** homeserver отримує зашифрований зміст, але бачить службові метадані Matrix. V1 не заявляє server-level контроль federation і не покладається на `m.federate: false`.

### Matrix E2EE

- **Значення:** наскрізне шифрування змісту Matrix-подій між перевіреними пристроями власника й бота.
- **Вживання:** точно описуємо захист транспорту й межу довіри.
- **Уникати:** стверджувати, що E2EE приховує службові метадані від homeserver або поширюється на GoDaddy, OpenAI чи Anthropic після розшифрування ботом.
- **Примітка:** E2EE завершується на verified Matrix device бота в GoDaddy Node runtime; розшифрований зміст існує в пам'яті runtime і передається OpenAI та, лише для Claude-маршруту, Anthropic через TLS.

### Згода на обробку даних

- **Значення:** одноразове підтвердження звичайної обробки бізнес-даних через `matrix.org`, GoDaddy, OpenAI та Anthropic.
- **Вживання:** описуємо перший запуск і базову межу передачі даних.
- **Уникати:** вважати її дозволом на особливо чутливий документ або зовнішню дію.
- **Примітка:** особливо чутливий документ потребує окремого підтвердження.

### Особливо чутливий документ

- **Значення:** документ, перед обробкою якого система має отримати окреме підтвердження власника.
- **Вживання:** спрацьовує підтверджена високоризикова межа даних.
- **Уникати:** мовчки обробляти його на підставі лише одноразової загальної згоди.
- **Примітка:** точна класифікація чутливості належить подальшому уточненню політик, але вимога окремого підтвердження вже є канонічною.

### Секрет

- **Значення:** пароль, API-ключ, OAuth token або refresh state, Codex `auth.json`, `CLAUDE_CODE_OAUTH_TOKEN`, recovery key, повні карткові чи банківські реквізити, державний ідентифікатор, медичні дані або інші дані, які за продуктовою політикою не можна приймати чи журналювати.
- **Вживання:** описуємо дані, які потрібно зупинити до передачі агентам і реєстрації, або захищати в окремому runtime secret store.
- **Уникати:** включати секрет до Matrix-повідомлення, агентського промпту, технічного журналу, архіву, експорту або клієнтського коду.
- **Примітка:** застосунок не приймає пароль Власника для входу. Google credentials і дані транзакції не передаються в Matrix, агентам, журнали чи архів (`FR-039`); AI OAuth-секрети мають окрему межу доступу.

### Архів сесій

- **Значення:** зашифроване безстрокове сховище завершених сесій із незмінним змістом і порядком підтверджених повідомлень.
- **Вживання:** описуємо подальший доступ, експорт, незмінність або видалення цілої сесії.
- **Уникати:** `історія чату`, якщо важливі гарантії шифрування й незмінності; `резервна копія`, якщо йдеться про канонічний архів.
- **Примітка:** окремі репліки завершеної сесії не редагуються й не видаляються.

### Облік витрат

- **Значення:** налаштовані щомісячні платежі за ChatGPT/Codex і Claude, фактичні інфраструктурні витрати та доступний provider usage/limit/reset status.
- **Вживання:** описуємо результат команди `Витрати`.
- **Уникати:** `вартість токенів сесії`, `фактична AI-вартість сесії` або `бюджетний ліміт`, якщо провайдер не нарахував і не надав відповідну суму.
- **Примітка:** AI-usage у межах підписки позначається як `входить у підписку` разом зі статусом квоти; невідома сума лишається невідомою. V1 не переходить на PAYG після вичерпання квоти.

### Налаштування власника

- **Значення:** єдина вузька адаптивна веб-поверхня V1 для параметрів майбутніх консультацій.
- **Вживання:** Власник переглядає або змінює незалежні блоки `Codex-агенти`, `Критик` чи `Швидкість консиліуму` на desktop або mobile.
- **Уникати:** `settings dashboard`, `чат`, `архів`, `admin console`, `панель керування`, `клієнтський кабінет` або назва повсякденного консультаційного UX.
- **Примітка:** повсякденна консультація лишається в Element/Matrix; ця поверхня не показує чат, live execution status або архів.

### Google-вхід Власника

- **Значення:** єдиний спосіб підтвердити особу для `Налаштувань власника` за `PI-AUTH-20260905`, `UC-003` і `FR-038`; після перевірки дозволеної ідентичності створюється окрема захищена локальна сесія.
- **Вживання:** описуємо вхід, відмову або повторний вхід до веб-поверхні.
- **Уникати:** змішувати з AI Subscription OAuth, Google-паролем у застосунку, локальним password fallback, іншим IdP або доказом MFA.
- **Примітка:** незалежні перевірки токена, браузерної транзакції та захисту запитів визначені `NFR-016.a`–`NFR-016.h`. Застосунок не вимагає власного другого фактора; перевірки самого Google не скасовуються. Збережена Console-конфігурація не означає успішного живого входу.

### Дозволена Google-ідентичність Власника

- **Значення:** стабільний Google `sub` у просторі довіреного issuer і точна дозволена підтверджена email-адреса за `NFR-016.b`.
- **Вживання:** описуємо серверну перевірку права єдиного Власника на веб-доступ.
- **Уникати:** `акаунт адміністратора Console`, display name, підказка вибору акаунта або перший успішний сторонній вхід як автоматичний доказ ролі.
- **Примітка:** конкретна прив'язка ще потребує підтвердження Власника до надання живого доступу; словник не встановлює значень `sub` чи email.

### Локальна сесія Власника

- **Значення:** окрема підписана захищена сесія застосунку після Google-входу, що дає доступ до налаштувань і перевіряється на сервері (`NFR-016.d`–`NFR-016.f`).
- **Вживання:** описуємо чинний веб-доступ, вихід, строки чинності або відкликання.
- **Уникати:** змішувати із сесією консультації, Google-сесією або Subscription OAuth; видавати Google-токен за сесію застосунку.
- **Примітка:** вихід, завершення строку й відкликання припиняють локальний доступ на сервері, включно після рестарту. Локальний вихід не означає виходу з Google й не змінює AI OAuth (`FR-039`, `UC-003`).

### Пароль власника — скасований спосіб входу

- **Значення:** історична назва локального пароля з попередньої версії контексту; цей спосіб замінений `PI-AUTH-20260905`.
- **Вживання:** лише пояснюємо історичне рішення або заборонений резервний вхід.
- **Уникати:** називати його чинним credential, користувацькою функцією або умовою відновлення доступу.
- **Примітка:** ні основний локальний пароль, ні його резервне використання не входять у V1; відновлення не повертає скасовану схему.

### Codex-агенти та Критик

- **Значення:** два незалежні блоки `Налаштувань власника`: модель і міркування головного/спеціалістів та окремі провайдер, модель і міркування Критика. Однаковий провайдер не об'єднує налаштувань.
- **Вживання:** Власник обирає модель або provider-specific міркування з типізованого списку поточно підтверджених значень.
- **Уникати:** довільний model slug, free-text input, спільний control міркування, одна спільна модель для обох провайдерів або неперевірена назва.
- **Примітка:** `FR-041` вимагає точних підтверджених назв і версій моделей; Claude впорядковано `Opus → Sonnet → Haiku`, а версії сімейства — від новіших до старіших. Каталоги й рівні окремо перевіряються для кожного провайдера за `FR-042`; згадка сімейства не доводить доступності конкретної версії.

### Provider-specific міркування

- **Значення:** незалежне значення міркування для конкретно вибраної моделі Codex або Claude Code; `За замовчуванням моделі` не передає явного effort (`FR-042`). Словник не встановлює машинного представлення цього вибору.
- **Вживання:** Власник задає рівень для одного провайдера, а система перевіряє його тільки за capability map цієї моделі.
- **Уникати:** спільну семантику між провайдерами, мовчазний downgrade, неперевірене значення або припущення, що однакова назва рівня має однакову інтенсивність.
- **Примітка:** поточні допустимі значення повертає Codex app-server або підтверджує практичний Claude Code probe; непідтримуване або невідоме поєднання fail closed блокує нову сесію.

### Швидкість консиліуму

- **Значення:** група `Налаштувань власника`, що визначає оркестраційний темп майбутньої консультації.
- **Вживання:** називаємо всю групу, в якій Власник обирає один `Пресет швидкості`.
- **Уникати:** `Claude Fast Mode`, платний speed mode, API/PAYG fallback або придбання usage credits.
- **Примітка:** `Швидкість` — короткий відповідник за очевидного контексту; повна назва групи за `FR-040` — `Швидкість консиліуму`. Вона змінює лише дозволену оркестрацію й не послаблює обов'язкових перевірок.

### Пресет швидкості

- **Значення:** одне з трьох значень `швидко / збалансовано / ретельно`, яке керує складом і паралельністю консиліуму, глибиною перевірок та очікуваним темпом.
- **Вживання:** називаємо конкретно вибране значення групи `Швидкість консиліуму`.
- **Уникати:** `Fast Mode`, `reasoning effort`, платний режим провайдера або гарантія скороченого часу за рахунок critic/A2A/E2EE/verbatim/safety/privacy.
- **Примітка:** жодний пресет не вмикає Claude Fast Mode, API/PAYG або usage credits.

### Фактичні налаштування сесії

- **Значення:** незмінний snapshot валідних значень груп `Codex-агенти`, `Критик` і `Швидкість консиліуму`, зафіксований для конкретної консультаційної сесії до першого залежного модельного виклику (`FR-045`, `UC-004`).
- **Вживання:** пояснюємо, з якими параметрами реально працює активна або завершена сесія.
- **Уникати:** `поточні defaults`, `останній saved set` або припущення, що save/reset посеред активної сесії змінює її роботу.
- **Примітка:** нове збереження застосовується лише до наступної сесії; несумісний набір не створює snapshot і блокує старт.

## 4. Дії користувача

### Надіслати запит

- **Значення:** надіслати текст, зображення або PDF у дозволену приватну E2EE Matrix-кімнату через Element.
- **Вживання:** описуємо початок прямої відповіді або консиліуму.
- **Уникати:** `створити тікет`, `запустити промпт`.
- **Примітка:** непідтримуваний тип вкладення має отримати зрозуміле повідомлення без запуску аналізу.

### Уточнити задачу

- **Значення:** надіслати нове звичайне повідомлення під час активної сесії; воно додається до поточного контексту.
- **Вживання:** власник коригує або доповнює активний запит.
- **Уникати:** створювати паралельну сесію без команди `Нова задача`.
- **Примітка:** слово `задача` зберігається в назві команди та природному описі роботи; об'єкт вхідного повідомлення канонічно називається `запит`.

### `Стоп`

- **Значення:** команда негайно припинити активну роботу поточної сесії.
- **Вживання:** власник хоче зупинити аналіз і подальші витрати.
- **Уникати:** продовжувати нові модельні виклики або публікувати пізні відповіді як продовження зупиненої роботи.
- **Примітка:** написання команди зберігати точно як `Стоп`.

### `Нова задача`

- **Значення:** команда закрити поточну сесію та створити нову без змішування контекстів.
- **Вживання:** власник переходить до іншої проблеми.
- **Уникати:** переносити робочий контекст попередньої задачі як активний контекст нової.
- **Примітка:** написання команди зберігати точно як `Нова задача`.

### `Витрати`

- **Значення:** команда показати налаштовані місячні платежі за AI-підписки, фактичні інфраструктурні витрати й доступний статус використання, ліміту або часу відновлення квоти.
- **Вживання:** власник перевіряє витрати.
- **Уникати:** подавати token estimate як фактичну суму, приписувати subscription usage ціну за сесію або називати команду механізмом жорсткого ліміту.
- **Примітка:** написання команди зберігати точно як `Витрати`; якщо провайдер не надає потрібний показник, відповідь каже `невідомо`.

### Підтвердити окремий дозвіл

- **Значення:** явно погодити обробку особливо чутливого документа, продовження понад 10 хвилин, зовнішню дію або іншу високоризикову межу.
- **Вживання:** система назвала конкретну дію, причину та межу дозволу.
- **Уникати:** виводити такий дозвіл із мовчання, загальної згоди на дані або попереднього дозволу на іншу дію.
- **Примітка:** дозвіл має бути окремим і явним.

### Експортувати сесію

- **Значення:** отримати повний запис однієї сесії зі збереженням змісту й порядку.
- **Вживання:** власник хоче перенести або зберегти сесію поза архівом.
- **Уникати:** експортувати лише переказ замість повної сесії.
- **Примітка:** експорт не змінює архівний запис.

### Видалити сесію

- **Значення:** остаточно видалити всю сесію після явного підтвердження.
- **Вживання:** власник контролює зберігання своїх даних.
- **Уникати:** `видалити репліку`, `відредагувати архів` або видалення без підтвердження.
- **Примітка:** окремі повідомлення завершеної сесії не видаляються.

## 5. Стани продукту

### Пряма відповідь

- **Значення:** робочий режим для короткого фактичного або очевидно простого запиту без зайвого консиліуму.
- **Вживання:** кілька фахових позицій чи незалежна критика не потрібні.
- **Уникати:** запускати агентів лише для демонстрації процесу.
- **Примітка:** це режим роботи, а не тип користувача.

### Консиліум

- **Значення:** робочий режим для складної, багатосферної, високоризикової або прямо позначеної користувачем задачі.
- **Вживання:** виконано хоча б одну підтверджену умову скликання.
- **Уникати:** використовувати для простого фактичного питання або невеликої безпечної дії.
- **Примітка:** див. також об'єкт `Консиліум` у розділі 3.

### Активна сесія

- **Значення:** поточна сесія, яка приймає уточнення й у межах якої триває робота.
- **Вживання:** описуємо єдиний активний контекст V1.
- **Уникати:** кілька паралельних активних сесій.
- **Примітка:** нове звичайне повідомлення додається саме до неї.

### Очікування дозволу

- **Значення:** сесія призупинила відповідну дію до окремого явного рішення власника.
- **Вживання:** потрібне продовження понад 10 хвилин, обробка особливо чутливого документа, зовнішня дія або інша підтверджена високоризикова межа.
- **Уникати:** називати станом помилки або мовчки продовжувати роботу.
- **Примітка:** причина й запит дозволу мають бути видимими.

### Зупинена сесія

- **Значення:** сесія, роботу якої власник припинив командою `Стоп`.
- **Вживання:** потрібно пояснити, чому нові виклики й пізні агентські повідомлення не продовжують цю роботу.
- **Уникати:** `завершена успішно`.
- **Примітка:** точний спільний lifecycle для сесій, закритих через `Нова задача`, залишається відкритим словниковим питанням.

### Завершена сесія

- **Значення:** сесія, у якій роботу завершено й канонічний запис переведено до зашифрованого незмінного архіву.
- **Вживання:** описуємо нормальне завершення, подальший експорт або видалення.
- **Уникати:** називати завершеною сесію з прихованим збоєм, неповним результатом або непідтвердженим архівом.
- **Примітка:** завершення не означає права редагувати окремі репліки.

### Збій або неповний результат

- **Значення:** видимий стан, коли агент, провайдер або частина роботи недоступні чи доказів недостатньо.
- **Вживання:** фактичний результат не відповідає повному успішному сценарію.
- **Уникати:** маскувати його статусом успіху або вигаданою реплікою.
- **Примітка:** система має назвати наслідок і наступну можливу дію.

## 6. Назви поверхонь і потоків

Канонічна поверхня повсякденної консультації — приватна Element/Matrix-кімната. Єдиний окремий продуктовий екран — адаптивні `Налаштування власника`.

Канонічні назви консультаційних потоків у Matrix-кімнаті:

- `Прийняття запиту`
- `Пряма відповідь`
- `Повний консиліум`
- `Живий перебіг консиліуму`
- `Уточнення активної сесії`
- `Зупинка сесії`
- `Нова задача`
- `Очікування дозволу`
- `Фінальна рекомендація`
- `Архів, експорт і видалення`

## 8. Внутрішні терміни

### Subscription OAuth

- **Значення:** автентифікація Codex або Claude Code через платну підписку єдиного власника без API-key/PAYG-білінгу.
- **Вживання:** описуємо єдиний дозволений AI auth mode V1.
- **Уникати:** називати API key еквівалентом Subscription OAuth, припускати платний fallback або змішувати його з `Google-входом Власника` або `Локальною сесією Власника` до налаштувань.
- **Примітка:** Google-вхід і локальна сесія Власника не авторизують Codex або Claude Code. Якщо Subscription OAuth або квота недоступні, залежна робота зупиняється; повторна авторизація відбувається лише через захищений позачатовий канал.

### Codex OAuth-стан

- **Значення:** один авторитетний захищений ChatGPT OAuth credential state, яким Codex керує та який штатно оновлює для всіх реальних агентських сесій/тредів власника.
- **Вживання:** описуємо Codex auth, managed refresh або захищене зберігання file-backed `auth.json`.
- **Уникати:** копіювати `auth.json` між незалежними runtime, вкладати його в образ, репозиторій, Matrix, промпти, логи чи архів.
- **Примітка:** один auth state не означає один агент: головний консультант і спеціалісти працюють у різних реальних Codex-сесіях/тредах.

### Claude Code OAuth token

- **Значення:** `CLAUDE_CODE_OAUTH_TOKEN`, створений командою `claude setup-token` для довіреної автоматизації в межах підписки власника.
- **Вживання:** описуємо автентифікацію Критика.
- **Уникати:** `ANTHROPIC_API_KEY`, API Console PAYG або передавання token через Matrix.
- **Примітка:** це секрет; його зберігання, відкликання й повторна авторизація відбуваються поза користувацьким чатом.

### Реальна Codex-сесія/тред

- **Значення:** окремо запущений контекст виконання одного Codex-агента з власною роллю, завданням і адресованими A2A-повідомленнями.
- **Вживання:** доводимо, що головний консультант і кожен спеціаліст є окремими агентами, а не ролями одного монологу.
- **Уникати:** `Matrix-тред`, `Сесія` користувацької задачі або окремий OAuth-акаунт для кожного агента.
- **Примітка:** усі такі сесії/треди використовують один Codex OAuth-стан власника, але мають незалежні робочі контексти.

### Fail-closed auth/quota

- **Значення:** правило, за яким runtime не запускає або зупиняє залежного агента, якщо subscription OAuth mode не підтверджено, refresh не вдався чи квоту вичерпано.
- **Вживання:** описуємо реакцію на auth/quota failure.
- **Уникати:** непомітний fallback на `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, PAYG або usage credits.
- **Примітка:** видиме повідомлення має назвати причину, доступний reset time і безпечний наступний крок, якщо ці дані відомі.

### GoDaddy Node runtime

- **Значення:** наявний GoDaddy Node.js app на стандартному GoDaddy hostname, у якому працює production server і verified Matrix device бота.
- **Вживання:** описуємо чинну hosting/runtime межу V1.
- **Уникати:** `Cloudflare runtime`, `Worker`, власний VPS або локальний Mac як чинний production target.
- **Примітка:** E2EE завершується на Matrix-пристрої бота в цьому runtime; це не розширює E2EE на OpenAI або Anthropic.

### GoDaddy Publish Secrets

- **Значення:** назва механізму захищених облікових даних GoDaddy, збережена з попереднього контексту; не підтверджує наявності потрібних значень або завершення їх надання.
- **Вживання:** посилаємося на цей механізм без розкриття значень; точне сховище й доступ до Google/AI credentials належать архітектурі за `NFR-006`.
- **Уникати:** hard-coded secret, client-visible value, Matrix-повідомлення, промпт, лог, архів або репозиторій.
- **Примітка:** назва механізму не відновлює локальний пароль і не є дозволом показувати, дублювати або змінювати секрет.

### MySQL-сховище

- **Значення:** GoDaddy/MySQL-еквівалент для Settings state, session registry і зашифрованого архіву.
- **Вживання:** описуємо чинну storage boundary V1.
- **Уникати:** `Durable Objects`, `R2` або plaintext archive як чинну вимогу.
- **Примітка:** архівні дані зберігаються лише як шифротекст прикладного рівня; ключі мають окремий lifecycle.

### Stateless Preview

- **Значення:** Preview без production/stateful credentials, спільної database schema або запису до production data stores.
- **Вживання:** описуємо безпечну Preview-межу до появи окремого isolation proof.
- **Уникати:** називати Preview stateful або production-equivalent лише через успішний render чи smoke test.
- **Примітка:** stateful Preview дозволяється лише після окремого доказу ізольованих schema, credentials і data boundary.

### Гейт незворотного очищення

- **Значення:** заборона видаляти legacy resource, secret, database або rollback artifact без recovery/restore evidence, точного переліку цілей і окремого just-in-time підтвердження.
- **Вживання:** міграція виявляє старі Cloudflare/Google resources або інший потенційний cleanup target.
- **Уникати:** трактувати міграцію, validated docs чи успішний deploy як дозвіл на cleanup.
- **Примітка:** це authorization boundary, а не окрема функція продукту.

### A2A

- **Значення:** підтверджений протокол адресованої міжагентної комунікації.
- **Вживання:** описуємо внутрішню взаємодію агентів або подальші технічні рішення.
- **Уникати:** використовувати абревіатуру без пояснення в першому користувацькому згадуванні.
- **Примітка:** точна версія та реалізація ще не визначені.

### Реєстратор

- **Значення:** функція головного консультанта, який підтверджує, упорядковує й реєструє міжагентні повідомлення.
- **Вживання:** описуємо внутрішню відповідальність за повноту й порядок.
- **Уникати:** створювати окрему роль `агент-реєстратор` без нового продуктового рішення.
- **Примітка:** міжагентні повідомлення в обхід головного консультанта-реєстратора заборонені.

### Канонічний порядок

- **Значення:** порядок підтвердженої реєстрації агентських повідомлень.
- **Вживання:** зіставляємо Element-відображення, архів та експорт.
- **Уникати:** покладатися на час доставки клієнтом як єдине джерело порядку.
- **Примітка:** конкретний механізм реалізації належить архітектурі.

### Незмінний журнал сесії

- **Значення:** внутрішній канонічний запис повного тіла й порядку підтверджених реплік, який після завершення не редагується.
- **Вживання:** описуємо цілісність, аудит або формування архіву.
- **Уникати:** `чат` як достатнє пояснення гарантії незмінності.
- **Примітка:** точний формат і сховище ще не визначені; старий локальний `CHAT.md` є evidence, а не автоматичною вимогою до формату Matrix V1.

### Allowlist

- **Значення:** внутрішній технічний механізм перевірки точної пари `room_id` і `owner_mxid` разом зі станом Matrix-пристрою.
- **Вживання:** у коді або інтеграційній документації доречний англійський термін.
- **Уникати:** у звичайному користувацькому тексті.
- **Примітка:** користувацький термін — `Дозволена Matrix-пара`; неперевірений або відкликаний пристрій не допускається.

### Нативне форматування Element/Matrix

- **Значення:** читабельне відображення заголовків, абзаців, списків, таблиць, посилань і коду засобами, сумісними з Element/Matrix, без сирого Markdown як коду чату.
- **Вживання:** описуємо формат видимої репліки.
- **Уникати:** обіцяти конкретний рендер без перевірки клієнта.
- **Примітка:** точні правила перетворення належать downstream-реалізації.

### `room_id`

- **Значення:** стабільний технічний ідентифікатор єдиної дозволеної Matrix-кімнати.
- **Вживання:** описуємо allowlist або перевірку вхідної Matrix-події.
- **Уникати:** показувати як службове поле у звичайній видимій репліці.
- **Примітка:** доступ визначає лише точна пара з `owner_mxid`, а не `room_id` окремо.

### `owner_mxid`

- **Значення:** повний Matrix user ID єдиного власника в allowlist.
- **Вживання:** описуємо технічну перевірку відправника.
- **Уникати:** називати номером телефону або вважати достатнім без `room_id` і перевіреного пристрою.
- **Примітка:** у звичайному користувацькому тексті використовувати роль `Власник`.

### Recovery key

- **Значення:** Matrix-механізм відновлення доступу до зашифрованих даних на новому пристрої.
- **Вживання:** описуємо контрольоване відновлення після заміни або втрати пристрою.
- **Уникати:** публікувати, журналювати чи передавати recovery key агентам або AI-провайдерам.
- **Примітка:** після відновлення новий Matrix-пристрій має пройти перевірку; втрачений або скомпрометований пристрій відкликається.

## 10. Терміни, яких слід уникати

- `воронка продажів`.
- `Публічний чатбот`, `SaaS`, `командний акаунт`, `клієнтський кабінет` — цих ролей і поверхонь немає у V1.
- `Живі партнери`, `реальні консультанти фірми` або твердження, що система працює у конкретній консалтинговій компанії.
- `Консиліум`, якщо фактично працював один агент або окремих агентів неможливо було запустити.
- `Незалежний доказ` для самої лише згоди кількох ШІ-агентів.
- `Думки агента`, `ланцюжок міркувань` або `прихований аналіз` як назва видимих реплік; користувач бачить лише фактично надіслані повідомлення.
- `Успішно завершено`, якщо є прихований збій, неповний результат, брак доказів або неперевірений архів.
- `Автоматично виконаємо` для повідомлень третім особам, публікацій, покупок, подання документів, кадрових рішень чи змін зовнішніх систем без окремого дозволу.
- `Browser chat`, `live-preview`, `settings dashboard`, `admin console`, `панель керування` або `архів` як назва `Налаштувань власника` чи повсякденної поверхні V1.
- `Cloudflare Access`, `Access JWT`, `Durable Objects` або `R2` як чинна вимога розміщення, доступу чи зберігання; вони допустимі лише в явно позначеному історичному контексті. Google-вхід є чинною окремою вимогою за `PI-AUTH-20260905`.
- `Google-вхід Власника` або `Локальна сесія Власника` як назва авторизації Codex/Claude Code; для AI-підписок канонічний термін — `Subscription OAuth`.
- `Subscription OAuth` як назва доступу до налаштувань; для нього потрібні `Google-вхід Власника` й окрема `Локальна сесія Власника`.
- `Пароль власника`, запасний локальний вхід, інший IdP або власна MFA застосунку як чинна функція MVP; рішення вже визначене `PI-AUTH-20260905`.
- `Моделі / Глибина міркування / Швидкість` як три чинні групи або `low / medium / high / xhigh` як спільна шкала Codex/Claude. Склад груп і незалежність значень визначають `FR-040`–`FR-042`.
- `Claude Fast Mode`, `Fast Mode`, `extra usage` або платний provider speed як синонім `Швидкості` чи `Пресету швидкості`.
- Довільний `model slug`, free-text model input або неперевірена назва моделі як доступний вибір V1.
- `Сім груп налаштувань`, `sound/motion settings`, `per-agent override` або `per-unit override` як функції `Налаштувань власника`.
- `WhatsApp` або `Meta WhatsApp Cloud API` як поточний канал V1; ці назви допустимі лише для історичного, superseded або out-of-scope контексту.
- `Власний VPS`, `власний Matrix homeserver` або `локальний Mac` як production-сервер V1.
- `Окремий Matrix-акаунт агента` для кожної видимої ролі; V1 використовує один Matrix-акаунт бота.
- `Власний звук`, `вшшшшух` або інший продуктовий звук; V1 покладається лише на нативні сповіщення Element та операційної системи.
- Твердження, що Matrix E2EE поширюється на GoDaddy, OpenAI чи Anthropic після розшифрування повідомлення verified Matrix device бота.
- Сирі технічні ID, номери повідомлень, секунди, системні інструкції, журнали інструментів і Markdown-маркери в користувацькому чаті.
- `Видалити окрему репліку` або `відредагувати завершену сесію` як доступні дії.
- `Бюджетний ліміт` як функція V1 до окремого підтвердженого рішення після збору фактичних витрат.
- `Фактична вартість модельних викликів сесії`, `token cost сесії` або інша сума, якої провайдер не нарахував і не надав.
- `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `API PAYG`, `автоматичні usage credits` або `fallback на API` як дозволений шлях продовження V1.
- Надсилання `auth.json`, OAuth token, refresh state або reauth URL/code через Matrix, агентський промпт, журнал чи архів.
- `Спільна підписка`, `доступ для клієнтів`, `доступ для команди`, `перепродаж агентів` або SaaS на OAuth-підписках власника.
