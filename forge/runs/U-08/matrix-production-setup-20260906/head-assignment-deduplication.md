# Повторені доручення головного — 2026-09-07

## Підтверджена причина

На запит власника перевірено Element і `ConsiliumRouter`. У видимій парі від 18:10 головний двічі публікував однаковий вступ щодо доопрацювання та повний текст задачі; відрізнявся лише адресат наприкінці — B2C-продажі або маркетинг. Це два окремо сформовані доручення, а не встановлений повтор доставки одного Matrix event. Код перед initial і revision виконував `assign` для кожного спеціаліста. За двох спеціалістів було п'ять head assignments; за п'яти — одинадцять.

## Ремонт

Головний тепер реєструє одне фактичне спільне доручення на кожен етап: первинні позиції, критика, доопрацювання. Угорі названі всі відповідні адресати. Повна задача наведена лише в першому дорученні; усі runtime виклики й надалі отримують незмінне поле task. Кожен адресат отримує дослівно те саме тіло доручення, що зареєстроване й показане в чаті до його виклику. Окремі первинні позиції, незалежна критика, індивідуальні revisions і один фінал залишені без об'єднання чи пропусків.

Нова вузька `routeHeadAssignment` перевіряє зареєстровану ідентичність головного, 1–5 різних наявних адресатів, безпечне тіло та чинну generation; реєстратор зберігає один запис і одну outbox-операцію. Список адресатів входить до наявного відбитка через addressedTo. Повтор того самого ID є replay, зміна адресатів під тим самим ID — conflict. Цей маршрут не створює Critic receipt та не послаблює Stop, видимість чи фінальний контроль.

Фільтрації, скорочення або редагування вже зареєстрованих реплік немає. Старі повідомлення, відбитки, Matrix transaction IDs, таблиці, crypto store, credentials та моделі не переписувалися. Чинні FR-009/011/014–018 збережені; approved baseline і доменні SDD-документи не змінювалися.
