# Реалізація адаптивної консультації та автономного Matrix

## Висновок і межі доказів

Реалізовано всі сім змін у гілці `codex/matrix-connection-20260906`. Це локально перевірений код, а не підтвердження його роботи на Published. Нових units не створено; чинний обсяг U-05/U-06/U-08/U-09, план PI-CONSENSUS-20260908. HappyPro, Google login, вибір моделей, production secrets, база даних, Matrix device/store і frozen design не змінені. Оплачуваних або локальних production-сервісів не додано.

## Кожна зміна

1. **Англійські назви.** Єдиний каталог 20 ролей; Head Consultant, Critic та спеціалісти мають англійські імена й адресатів. Старі підписи відображаються через сумісне зіставлення, історичні записи не переписуються. Службові повідомлення явно відокремлені від реплік спеціалістів.
2. **Візуальне розрізнення.** Доречні emoji з текстовими іменами працюють за замовчуванням. Для клієнта з підтвердженою підтримкою кольорів підготовлено сім окремих збережених слотів; сама назва не залежить від кольору. Реальні Element теми/екрани ще не перевірено.
3. **Мова розмови.** Перший змістовний запит визначає мову через Head; явний вибір має пріоритет, цитати/код/вкладення не перемикають її. Мова зберігається після Continue/restart. Для семи мов є вбудовані службові тексти; інші використовують після згоди окремий переклад лише фіксованих рядків застосунку через вже вибрану Codex-підписку, із перевіркою ключів, команд і hash та кешем. Задача, історія та документи до перекладача не потрапляють. До згоди невідомий переклад явно позначений як неперекладений; модель не викликається.
4. **Сім особистих ролей.** Personal Coach / Growth Consultant, Fitness Coach, Longevity Coach, Personal Wealth Coach, Relationship Coach, Psychologist, Psychotherapist. Усі є ШІ-ролями, а не заявою про ліцензію. Промпти обмежують діагностику, лікування, гарантії, чутливі дані й особисті запитання без згоди. Типізований кризовий handoff зупиняє звичайний консенсус, зокрема посеред обміну.
5. **Реальні окремі доручення.** Head обирає 2–5 доречних спеціалістів за чинним preset та повертає для кожного окремі question/outcome/facts/constraints/dependencies. Дублікати, невідомі ролі й циклічні залежності відхиляються. Незалежні первинні відповіді не отримують чужу відповідь наперед.
6. **Консенсус і межа Критика.** Спеціалісти, обраний окремий Critic і Head явно погоджують одну поточну пропозицію з прив'язкою до позицій. Зміни скасовують старі погодження; фінальний текст точно збігається з погодженим. Підтверджена репліка, лічильники та outbox записуються однією транзакцією. Кожен спеціаліст має максимум сім Critic-повідомлень; multicast враховується для всіх адресатів, восьма репліка заблокована. Continue/restart не обнуляє бюджет. Без згоди результат чесно позначається unresolved. Обидва провайдери Критика збережені без змішування налаштувань.
7. **Автономний Matrix.** Типізовано помилки сховища; тільки відомі тимчасові збої автоматично повторюються з обмеженою затримкою. Є автоматичне пробне відновлення після розмикання circuit та один fenced worker. Додано opt-in same-app endpoint `/_matrix/push/v1/notify`: він перевіряє bounded hint і лише будить authenticated E2EE sync, ніколи не приймає push-текст як задачу й не викликає агентів. Додано окремий явний реєстратор pusher/rule, який зберігає інші записи. Новий ключ/реєстрацію на Published не виконано.

## Додаткові виправлення під час інтеграції

- Транзакції тестового сховища тепер серіалізовані, як у production MySQL adapter; rollback не губить паралельні записи.
- Ключі MySQL JSON можуть змінювати порядок без хибного idempotency conflict; поточний durable consensus має цілісність і сувору перевірку форми.
- Critic не може адресувати спеціаліста, не збільшивши його лічильник; старий append/finalization не обходить новий consensus ledger.
- Пізнє повернення executor після атомарного фіналу або safety handoff більше не перетворює задачу на Continue. Registrar перевіряє terminal state в самій транзакції revision.
- Hash задачі включає підтверджені manifests вкладень, тому новий PDF/образ не зберігає застарілі погодження.
- Continue читає додані зображення окремим observation-only викликом, зберігаючи команду й лічильники; спостереження повністю надходить команді.
- Locale та final/proposal/safety metadata зв'язані з fingerprint у SQL outbox: зміна/видалення відхиляється.
- Неповні adaptive-параметри, навіть лише taskDigest, не вмикають старий обхідний шлях.

## Перевірки та невиконане

Точні команди, результат, час і SHA-256 змінених implementation-файлів наведено у `verification.json`. Використано Node.js 22.16.0, Darwin arm64, синтетичні дані, fake RPC, локальне/скриптоване сховище. Справжні production entry points перевірено в інтеграції, але фактичних Codex/Claude/Matrix запитів чи MySQL-сервера в цьому запуску не було.

QA-CNS-001–008 мають часткові локальні докази. Повні checks не оголошені passed. QA-CNS-009/010, actual Element visual/heuristic/user evidence, Published idle/restart/redeploy і справжня доставка лишаються not_run. Історичний blocked release не скасовано; інші старі evidence не підмінені новими тестами.

Чинний pinned Rust модуль досі повертає узагальнене початкове `not_ready` для частини auth/policy/network відмов. Повтор використовує той самий store/device та не обходить перевірки; це не доводить точну причину production відмови. Missing/corrupt/inaccessible/mismatched state не перестворюється. Якщо provider call перервався невизначено, новий обмежений цикл потребує явного Continue у Matrix, не входу в Settings.

## Наступний конкретний крок

Після окремого дозволу: розгорнути цю перевірену гілку на чинному Published через Chrome; зберегти існуючу ідентичність і БД; створити dedicated `MATRIX_WAKE_PUSH_KEY`, увімкнути `MATRIX_WAKE_ENABLED=TRUE`; виконати dry-run, потім `scripts/register-matrix-wake.ts --apply`. Покрокова процедура і точні змінні — у `scripts/matrix-wake-operator.md`.

Потім із закритими Settings перевірити одну англійську й одну українську консультацію, контрольований unresolved та одну повторну подію; після дозволеного idle/restart/redeploy звірити незмінні device/store/cursor й один результат. Лише фактичні спостереження можуть закрити відповідні live/user gates.
